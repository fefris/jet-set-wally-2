# Jet Set Wally II — Plan

A faithful-feeling browser homage to **Jet Set Willy II** (Software Projects, 1985): the same engine
mechanics, ZX Spectrum presentation and gameplay rules, with an **original** hero (Wally), original rooms,
sprites and names, and public-domain music. Research backing every number below: `docs/research.md`
(raw notes: `out/research_*.md`).

---

## 1. Goals & acceptance criteria

| # | Criterion | How it is verified |
|---|---|---|
| G1 | Plays like JSW II: 2 px/frame walk, 18-frame jump (20 px peak, 36 px span), 4 px/frame falls, fatal falls, one-way floors, ramps, conveyors, ropes, arrows, guardians, items, lives, room flipping | Headless physics unit tests against the research tables |
| G2 | Looks like a Spectrum game: 256×192, 8×8 attribute colour cells, bright/flash, border colour, colour clash, status area | Screenshot review of every room |
| G3 | ~134 rooms in the same macro-shape as JSW II (mansion hub, roof/attic, towers, cellars, mines, well, grounds & giant tree, coast & yacht & island, sewers, starship, alien planet, nightmare ending room) | World plan + map render |
| G4 | **Every room connects correctly** | `tools/validate.js` (structure) + `tools/solve.js` (physics reachability) must pass with zero errors |
| G5 | Every item and every room reachable from the start; no soft-locks; every room returns to the hub; no infinite death loops | Solver: forward + backward reachability over real physics |
| G6 | Runs by double-clicking `index.html` (no server, no build) and as a single-file `dist/jetsetwally2.html` | Browser run + screenshot |

## 2. Architecture

Plain JavaScript classic scripts on a global `JSW` namespace — no dependencies, no build step.
`src/manifest.json` gives load order (`@data` = every file under `src/data/`). Node tools load the same scripts
through `tools/load.js` (vm context), so **the solver runs the real game engine**.

```
index.html                  dev entry (generated by tools/gen-index.js from the manifest)
src/core/registry.js        defineSprite / defineTile / defineItem / defineFont / defineTune / defineRoom
src/render/screen.js        Spectrum display: 256x192 bitmap + 32x24 attributes + border -> RGBA
src/render/text.js, draw.js text, tiles, items, sprites, status bar
src/engine/room.js          room compiler (legend -> cell types/styles, items, guardians)
src/engine/world.js         builds the world, derives exits from grid positions, reciprocity
src/engine/willy.js         Wally physics (pure, headless) — JSW-exact state machine
src/engine/entities.js      guardians (h/v/diagonal), arrows, ropes, lifts
src/engine/game.js          game state machine: title, play, death, game over, ending; items, lives, clock
src/audio/beeper.js         WebAudio square-wave beeper, tunes, SFX
src/main.js                 browser boot, input, fixed-timestep loop, canvas scaling
src/data/**                 sprites, tiles, items, font, tunes, rooms (one file per region)
tools/                      load, preview, validate, solve, render-map, gen-index, build, test
```

## 3. Engine rules (decisions)

Units: pixels. Willy's x = `col*8 + frame*2` (col 0..30, frame 0..3). All per-frame figures are per **logic frame**.

* **Timing** — fixed-timestep logic at **20 fps** (JSW II ran ~18–25 fps; JSW I ~11–14). Options: 14 / 20 / 25.
  FLASH swaps every 320 ms real time. Rendering at display refresh.
* **Input** (JSW II style, read once per frame): left `Q E T U O` / ←, right `W R Y I P` / →, jump = bottom row
  (`Z X C V B N M`, Space, Shift) / ↑; pause `A S D F G`; music toggle `H J K L Enter`; quit `Esc`.
  Gamepad = Kempston equivalent.
* **Walking** — JSW flag table: turning costs one frame with no movement; both keys = keep doing what you were doing.
  Only **wall** cells block sideways (checks: leading column rows y+1(+dy), y+2 if spanning 3 rows, and the head —
  we check the head in both directions, fixing JSW I's "Don't mind your head" bug). Room edge check before wall check.
* **Jump** — 18 frames, Δy by counter J: −4,−4,−3,−3,−2,−2,−1,−1,0,0,+1,+1,+2,+2,+3,+3,+4,+4. Horizontal 2 px step on
  take-off and each jump frame (not on landing-check frames that land). No steering mid-air. Landing checks at J=13
  and J=16 (and every aligned frame of the descent). **JSW II changes adopted**: a jump pressed on a turning frame
  carries horizontal motion (step forward from standstill), and no dead frame when the jump ends.
  Ceiling = **wall only**: y snaps down to the cell grid, jump cancelled, fall begins.
* **Falling** — airborne counter: walk-off frame 0→2 (no movement), then +1 per frame with y += 4, 16 wraps to 12.
  Jump end sets 6. Landing with counter ≥ 12 is fatal ⇒ safe walk-off drop ≤ 4 cells (32 px); safe drop after a
  jump ≤ 2 cells below take-off. Walking off a ledge = straight vertical drop.
* **Support** — only checked when y is cell-aligned. Supported if either cell under the 2-cell footprint is
  floor / wall / ramp / conveyor, and neither is a nasty. **Floors are one-way** (jump up through them).
* **Ramps** (`/` rises right, `\` rises left, any number per room) — JSW step logic when crossing a cell boundary
  on the ground: up/down one row, visual offset B = 2·frame or 6−2·frame px. Walk up past the top ⇒ room above.
* **Conveyors** (`<` `>` any number) — fake a key press in the belt's direction; walking against it only works if
  already moving that way; JSW II edge quirk ignored.
* **Nasties** — attribute/cell based: any nasty in Willy's 2×3 block (incl. the row under his feet) kills.
* **Items** — collected when their cell is inside Willy's white-recoloured block (2×2, or 2×3 when mid-cell).
  Ink cycles magenta→green→cyan→yellow every frame, phase-offset per item. Guardians/arrows never collect (bug fixed).
* **Room transitions** — left: col=30 (frame kept); right: col=0 (frame kept); both keep jump/fall state.
  Up (jump/ramp/rope takes y<0): y=104, airborne=0 (jump ends). Down (aligned, feet row would be 16): y=0,
  airborne=2 unless already ≥11 (fatal falls stay fatal).
* **Guardians** — pixel-perfect collision against **Willy's pixels only** (JSW I also killed on tile overlap —
  fixed). Colour = guardian INK over the cell PAPER on the 2×2/2×3 block (colour clash kept).
  * horizontal: 2 px/frame (4 frames per cell), pre-shift by frame, bounds in cells, 1-frame pause when turning;
    optional `speed: 2`. Art faces right; mirrored when moving left.
  * vertical: y += dy (±1..6 px), clamp both bounds (JSW I underflow bug fixed); animation every frame (`fast`)
    or every other frame (`slow`).
  * diagonal (JSW II): (dx, dy) per frame for `count` frames, then reverse.
  * arrows: 1 cell/frame over a 256-frame lap, visible 32 frames, rising-zip warning ~12 frames before.
  * ropes: JSW table-driven swing (33 one-pixel segments, 90-frame period, ±67 px), grab on pixel contact, climb
    1 segment/frame (down if facing the swing direction), jump off in facing direction, 16-frame re-grab cooldown;
    climbing off the top ⇒ room above (if exit).
  * lifts (JSW II): runs of floor cells moving one cell every `period` frames between two rows; carry Willy.
* **Death & respawn** — room flashes through INK 7→0 with falling notes; lose a life; respawn at the **last static
  solid ground** Willy stood on (JSW II rule, possibly in a previous room), room re-initialised, then **2 s of
  invulnerability** (Willy flickers) so death loops are impossible. Items stay collected.
* **Lives** — 7 spare (8 total), shown as dancing Wallys in rows 22–23 (bright blue, red, magenta, green, cyan, yellow, white).
  Music pitch rises with more lives ("music of life").
* **Clock** — JSW II elapsed timer `HHHH:MM:SS`, 1 s per 10 frames, blinking colons; no deadline.
* **HUD** — row 16 room name (centred, white); row 19 `Rooms 001  TIME  0000:00:00` (bright white); row 22 `Items : 000`
  (bright yellow) beside the lives.
* **Objective** — ~175 items; the housekeeper leaves the Master Bedroom once **150** are collected. Touching the bed
  (a right conveyor) starts the forced run right (4 px/frame, no jumping) through the ending path to the toilet ⇒
  the nightmare ending room, Wally jumping on the spot, then a results screen (time, rooms, items).
  Before winning, the toilet is harmless decor.
* **Game over** — Wally on a plinth; an anvil lowers on a lengthening chain, paper colour cycling, rising tone; "GAME OVER" glitters.
* **Title** — big flashing block-letter logo + mansion picture built from coloured cells and slope tiles, scrolling message,
  Moonlight Sonata (public domain) with the two-note octave style. In game: Grieg's *In the Hall of the Mountain King* (PD).
* **JSW II specials** (data-driven, per room `special`): teleport pads, rocket launch (after the room's items are taken),
  trip switch + yacht voyage to the island, lifts, flashing nasties, forced-run-right rooms on the ending path,
  housekeeper/bed/toilet, "cartography" map room (decorative live map of visited rooms).

## 4. Room data format

```js
JSW.defineRoom({
  id: 'master_bedroom',          // unique snake_case
  name: 'Master Bedroom',        // <= 32 chars, centred on row 16
  region: 'mansion',
  pos: [9, 8],                   // world grid [col, row]; exits are the grid neighbours
  border: 'red',
  item: 'key',                   // 8x8 item graphic for this room
  tiles: {                       // legend: one char -> tile style
    '.': { type: 'air',   ink: 'white', paper: 'black' },               // exactly one air symbol
    '=': { type: 'floor', tile: 'plank', ink: 'yellow', paper: 'black' },
    '#': { type: 'wall',  tile: 'brick', ink: 'red', paper: 'yellow' },
    '^': { type: 'nasty', tile: 'spikes_up', ink: 'green', paper: 'black', bright: true },
    '/': { type: 'ramp',  tile: 'stairs', ink: 'white', paper: 'black' },   // '/' rises right, '\' rises left
    '<': { type: 'conveyor', tile: 'belt', ink: 'cyan', paper: 'black', dir: 'left' },
  },
  map: [ /* 16 strings x 32 chars; '+' = item on air */ ],
  guardians: [
    { type: 'h', sprite: 'butler', ink: 'cyan', bright: true, x: 12, y: 104, min: 6, max: 20, dir: 'left' },
    { type: 'v', sprite: 'ghost', ink: 'white', x: 20, y: 16, min: 8, max: 88, dy: 2, anim: 'fast' },
    { type: 'd', sprite: 'comet', ink: 'yellow', x: 40, y: 20, dx: 2, dy: 2, count: 30 },
    { type: 'arrow', dir: 'left', y: 42 },
    { type: 'rope', x: 16, length: 32 },
    { type: 'lift', x: 10, width: 3, top: 6, bottom: 13, period: 4, start: 13, dir: 'up' },
  ],
  exits: { up: null },           // optional: override grid-derived exits (null = none, or a room id)
  special: { },                  // optional JSW II special behaviours
  start: [x, y],                 // only in the start room (cell x, pixel y)
});
```
Rules: tile types must differ in behaviour only by `type` (no attribute-collision bugs); a room has ≤ 8
guardians+arrows (+1 rope), ≤ 16 items; guardian paths only over air; background INK never white.

## 5. Room-connection rules ("all rooms connect correctly")

Two rooms that are grid neighbours are **connected** exactly when their shared edge is open; otherwise both
sides of the edge must be sealed with wall. Enforced by `tools/validate.js` and proven by `tools/solve.js`.

* **Left/right door** (A on the left, B on the right): for every row, A's columns 30–31 and B's columns 0–1 must
  agree: wall ⇔ wall, and walkable surfaces (floor/wall/ramp/conveyor tops) continue across at the same row, so
  Willy never enters inside a wall or drops unexpectedly. Openings must be ≥ 2 rows tall (Willy is 16 px).
* **Down (drop) shaft**: upper row 15 is air over the span; lower rows 0–1 are air over the span; a landing
  surface in the lower room within 4 cells (rows ≤ 6) or a continuing shaft (the fall counter resets per room).
* **Up (climb)**: lower row 0 non-wall over the span with a jumping ledge at row ≤ 4 beneath it; upper room rows
  13–14 non-wall and a row-15 floor to land on (Willy arrives at y=104 standing still).
* **Stairs across a boundary**: a ramp that runs off the top of the lower room continues from row 15 of the upper room.
* **Ropes**: a rope whose top touches row 0 lets Willy climb into the room above (needs the landing floor).
* **Sealed**: the whole shared edge is wall on both sides.
* **One-way links** (sewer drain, outfall, rocket, yacht voyage, teleports) are declared in `special` and must
  land Willy on safe ground; the solver treats them as directed edges.

**Solver** (`tools/solve.js`): breadth-first search over the *real* engine step function (room, col, frame, y,
facing, moving, airborne, jump counter, rope/lift phase) with every input combination per frame, guardians
ignored (static geometry). Reports: unreachable rooms, unreachable items, edges that lead nowhere or into walls,
fatal entry points, rooms from which the start region is unreachable (soft-locks), and per-room coverage.
Guardian sanity (paths over air, not camping on entry points or item cells) is checked separately.

## 6. World structure (original layout, JSW II macro-shape)

~134 rooms on one integer grid, regions placed apart where they are reached by special transport:

| Region | ≈ Rooms | Reached by |
|---|---|---|
| Mansion (4 floors: cellar-level halls, ground, first, top) incl. start room (Bathroom) and Master Bedroom | 32 | hub |
| Roof & attic | 14 | stairs from top floor |
| Towers (watch tower, belfry, rocket silo) | 4 | roof |
| Cellars corridor & wine vaults | 10 | mansion stairs |
| Mines & caves | 8 | cellars |
| Well shaft (death-trap gag, respawn-safe) | 3 | mines |
| Grounds east: drive, gatehouse, garden, giant tree (trunk, branches, canopy, roots), river & bridge, corner shop | 20 | front door |
| Coast west: beach, pier, yacht (2), sea, island | 7 | cellars/back door |
| Sewers | 7 | one-way drain from the mansion ⇒ outfall onto the beach |
| Starship | 20 | rocket (one-way) / island teleport; return teleport to the Bathroom |
| Alien planet | 8 | teleport pads from the starship (loop) |
| Nightmare ending room | 1 | toilet after winning |

Detailed per-room plan (names, positions, links, door contracts, items, guardians, specials) lives in
`docs/WORLD.md` and `src/data/world_plan.json`, produced by the world-design phase.

## 7. Phases

1. **Research** ✅ — `docs/research.md`.

7. **Specials, music, title, game over, ending.**
8. **Verification** — full-world solver (zero errors), per-room visual review, headless play-throughs, browser run.
9. **Ship** — single-file build, README with controls.
